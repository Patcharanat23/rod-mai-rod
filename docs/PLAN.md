# PLAN.md - แผน 5 วัน

มีเวลา 5 วัน 8 คน 9 โมดูล (โมดูล 1 เสร็จแล้ว เจ้าของโปรเจกต์ดูแลต่อและรีวิว) สเปกเต็มทำไม่ทัน **เป้าหมายคือเวอร์ชันถอยใน RUNBOOK หัวข้อ E ให้ครบทุกโมดูลก่อน** แล้วค่อยเติมของเสริมถ้าเหลือเวลา
ทุกคนทำงานบน stub ที่ต่อกันครบแล้ว (api-backend > routing-engine > risk-decision > weather-disaster ส่งต่อกันจริง) แก้แค่ข้างในโมดูลตัวเอง รูปแบบข้อมูลไม่เปลี่ยน

## ต้องมี / ถ้าเหลือเวลา

| โมดูล | ต้องมี (วันที่ 4 ต้องเสร็จ) | ถ้าเหลือเวลา |
|---|---|---|
| 1 web-overview | เสร็จแล้ว (มี `EmergencyCard` ใน `shared/` ให้หน้าอื่นใช้) | - |
| 2 web-mytrip | ฟอร์มสร้างทริป + ปุ่ม Plan + เส้นทางบนแผนที่ + popup สรุป + แท็บขวา + `EmergencyCard` เมื่อเส้นทางเป็น HIGH | หลายเส้นทางให้เลือกดู, ใช้ตำแหน่งปัจจุบัน, แก้ทริป |
| 3 web-safety-assistant | หมุดสีตามระดับ + popup รายละเอียด + แชทข้อความธรรมดา | ไอคอนตามชนิดภัย, marker cluster, การ์ด actions |
| 4 api-backend | Postgres + register/login จริง (bcrypt + JWT) + ตรวจเจ้าของทริป | `/health` เช็คฐานข้อมูล |
| 5 routing-engine | เส้นทางจริงจาก OSRM + เวลาถึงแต่ละหมุด + จุดตัวอย่างทุก 20 กม. | cache, DEMO_MODE, สร้างเส้นเลี่ยงเอง |
| 6 weather-disaster | Open-Meteo รายชั่วโมง ณ เวลาที่ขอ + GDACS | USGS, cache, ดินถล่มแบบประเมิน, DEMO_MODE |
| 7 risk-decision | หมุดภัยในรัศมี 20 กม. + `risk_score` ตามความรุนแรง + `summary_th` ที่บอกว่าเสี่ยงตรงไหน | `DELAY` |
| 8 assistant-agent | คำสั่งแบบกฎตายตัว 3 แบบ (RUNBOOK หัวข้อ B) + ถามตอบผ่าน LLM + ใช้ `safety_search()` ตอบคำถามความปลอดภัย | LLM สั่งแก้ทริปด้วย function calling, ตัวสำรอง |
| 9 safety-knowledge | คำแนะนำฉุกเฉินครบทุกชนิดภัยพร้อมแหล่งที่มา + ค้นภาษาไทยได้ | ค้นด้วย embeddings |

**ตัดออกจากรอบนี้**: Thaiwater, TMD, deploy ขึ้น Vercel

## รายวัน

| วัน | ทุกคน | เจ้าของโปรเจกต์ |
|---|---|---|
| 1 | clone, `make up && make health && make smoke` ผ่านบนเครื่องตัวเอง, อ่าน README ของโมดูล, เปิด PR แรกเล็กๆ ภายในวันนี้ (แค่ทำให้เห็นว่า flow ใช้ได้) | ตั้ง Discord, ตอบคำถามเรื่องการติดตั้ง |
| 2 | งาน "ต้องมี" ครึ่งแรก เปิด PR อย่างน้อย 1 อัน | รีวิว 2 รอบต่อวัน (เที่ยง, สามทุ่ม) |
| 3 | งาน "ต้องมี" ครึ่งหลัง | ตอนเย็น merge `dev` เข้า `main` ครั้งแรก ต้องผ่าน smoke |
| 4 | **ปิดงาน "ต้องมี" ให้ครบ** เที่ยงวันแล้วโมดูลไหนยังไม่เสร็จ ตัดเหลือเวอร์ชันถอยทันที ช่วงบ่ายทุกคนทดสอบเส้นหลักบนเว็บจริง | ตัดสินใจว่าอะไรตัด |
| 5 | แก้บั๊กเท่านั้น ห้ามเพิ่มฟีเจอร์ เตรียมทริปตัวอย่าง อัดวิดีโอสำรอง (RUNBOOK หัวข้อ F) | merge เข้า `main` รอบสุดท้าย |

## กติกาให้ทันเวลา

- **PR เล็ก** ไม่เกินประมาณ 300 บรรทัด เปิดบ่อยดีกว่าเปิดทีเดียวตอนจบ รีวิวทันและหาบั๊กง่าย
- ติดเกิน 1 ชั่วโมง ทักในกลุ่มทันที อย่านั่งเงียบ
- `pytest` ในโมดูลตัวเองต้องผ่านก่อนเปิด PR และ CI ต้องเขียว (ดูแท็บ Checks ในหน้า PR)
- ทุกคนดูที่ `TODO(<module-slug>)` ในโค้ดของตัวเองก่อน เป็นจุดที่ตั้งใจเว้นไว้ให้เติม
- ห้ามเปลี่ยนรูปแบบข้อมูลใน CONTRACT เอง ถ้าจำเป็นต้องเปลี่ยน ทักเจ้าของโปรเจกต์ก่อน
