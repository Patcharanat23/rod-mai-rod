# safety-knowledge (โมดูล 9)

**หน้าที่**: คลังความรู้ด้านความปลอดภัย (Disaster RAG) ค้นคำแนะนำจากเอกสาร และตอบคำแนะนำฉุกเฉิน + เบอร์ติดต่อตามชนิดภัย
**ผู้รับผิดชอบ**: Phitphibul Phrompheak (@phitphibul67)
**branch**: `feature/safety-knowledge/<ชื่อ>`
**endpoint**: `POST /api/v1/safety/search`, `GET /api/v1/safety/emergency` (`docs/CONTRACT.md` หัวข้อ 6)
**เรียกใคร**: ไม่มี (อ่านไฟล์ใน `knowledge/` เท่านั้น)
**ใครเรียกเรา**: assistant-agent (ตอบคำถามเรื่องความปลอดภัย), api-backend (ส่งคำแนะนำฉุกเฉินให้หน้าเว็บ)

## รันเดี่ยว

```bash
pip install -r requirements.txt pytest
uvicorn app:app --reload --port 8000
pytest
```

## เริ่มจากตรงไหน

1. **เอกสาร** เพิ่มไฟล์ใน `knowledge/` ให้ครบทุก `hazard_type` (ฝน ฝนหนัก ลมแรง น้ำท่วม ดินถล่ม พายุ แผ่นดินไหว) และการขับรถช่วงอากาศแย่ เขียนสั้น ข้อละบรรทัด ใส่ `source` เป็นชื่อเอกสารหรือเว็บจริงที่สรุปมา (เช่น เว็บ ปภ.) ไฟล์ตัวอย่าง 2 ไฟล์ตอนนี้ยังไม่มีแหล่งที่มาจริง ต้องแทน
2. **คำแนะนำฉุกเฉิน** เติม `EMERGENCY` ให้ครบทุกชนิดภัย หรือย้ายไปอ่านจากไฟล์
3. **การค้น** แก้ `score()` ให้ค้นภาษาไทยได้จริง (ข้อ 1 ด้านล่าง)
4. ถ้าเหลือเวลา เปลี่ยนเป็นค้นด้วย embeddings (ต้องทักเจ้าของโปรเจกต์ก่อนเพิ่ม library)

## จุดที่คนส่วนใหญ่พลาด (อ่านก่อนเขียน)

1. **ภาษาไทยไม่มีเว้นวรรคระหว่างคำ** `"น้ำท่วมต้องทำยังไง".split()` ได้ก้อนเดียวทั้งประโยค เลยค้นไม่เจอ แก้ได้ 2 แบบ: ตัดคำด้วย `pythainlp` (ต้องขอเพิ่ม library) หรือเทียบแบบ character n-gram (เช่น ตัดทีละ 3 ตัวอักษร) ซึ่งไม่ต้องใช้ library เพิ่ม เขียนเทสต์ด้วยประโยคจริงที่ผู้ใช้จะพิมพ์
2. **แต่งคำแนะนำเอง** ข้อมูลความปลอดภัยผิดเป็นอันตรายจริง ทุกข้อความต้องมาจากเอกสารที่มีแหล่งที่มา และคืน `source` กลับไปทุกครั้ง ห้ามให้ LLM เขียนเนื้อหาในคลังนี้
3. **เบอร์ฉุกเฉินผิด** ตรวจทุกเบอร์กับเว็บทางการก่อนใส่ แล้วอย่าใส่เบอร์ที่ไม่แน่ใจ
4. **คืนเอกสารทั้งไฟล์** assistant-agent จะส่งผลค้นต่อให้ LLM คืนแค่ข้อความสั้นๆ ที่เกี่ยวข้อง (`limit` ข้อ) ไม่งั้นเปลือง token และคำตอบเยิ่นเย้อ
5. **ค้นไม่เจอแล้วตอบ error** ไม่เจอให้คืน `results: []` แล้วให้คนเรียกตัดสินใจเอง
6. **อ่านไฟล์ใหม่ทุกคำขอ** โหลดครั้งเดียวตอนเริ่ม (`DOCS` ใน stub) แก้ไฟล์แล้ว restart container
7. **ชนิดภัยไม่ตรง CONTRACT** ใช้ `hazard_type` ชุดเดียวกับ CONTRACT หัวข้อ 4 เท่านั้น เทสต์ในโฟลเดอร์นี้ตรวจให้แล้ว

## ถือว่าเสร็จเมื่อ

- ทุก `hazard_type` มีคำแนะนำฉุกเฉินพร้อมแหล่งที่มา
- ค้น "น้ำท่วมต้องทำยังไง" (ไม่มีเว้นวรรค) แล้วได้ข้อความจากเอกสารน้ำท่วม
- `pytest` ผ่าน
