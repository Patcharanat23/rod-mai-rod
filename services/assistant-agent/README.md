# assistant-agent (โมดูล 8)

**หน้าที่**: แชทถามตอบเรื่องเที่ยว และรับคำสั่งสร้าง/แก้/ลบทริปแล้วทำจริงผ่าน api-backend
**ผู้รับผิดชอบ**: Patcharanat Budploy (@Patcharanat23)
**branch**: `feature/assistant-agent/<ชื่อ>`
**endpoint**: `POST /api/v1/chat` (`docs/CONTRACT.md` หัวข้อ 6)
**เรียกใคร**: LLM (ไลบรารี `openai` + `base_url`), api-backend, safety-knowledge (`safety_search()` ใน `app.py`)
**ใครเรียกเรา**: api-backend

## รันเดี่ยว

```bash
pip install -r requirements.txt
uvicorn app:app --reload --port 8000
```

## จุดที่คนส่วนใหญ่พลาด (อ่านก่อนเขียน)

1. **แชทบอกว่าแก้แล้ว แต่ข้อมูลไม่ได้เปลี่ยน** ใช้ function calling แล้วเรียก api-backend จริง ตอบว่าสำเร็จได้ก็ต่อเมื่อ api-backend ตอบ `"error": null` แล้วเท่านั้น และต้องใส่ `actions` ให้หน้าเว็บรู้ว่าต้องโหลดข้อมูลใหม่
2. **เลื่อนทริปแล้วไม่แพลนใหม่** เวลาเปลี่ยน พยากรณ์ก็เปลี่ยน หลัง PATCH สำเร็จให้เรียก `POST /trips/{id}/plan` ต่อ แล้วบอกผู้ใช้ว่าความเสี่ยงใหม่เป็นยังไง
3. **"Trip 01" หาไม่เจอ** ผู้ใช้พูดถึงทริปด้วย `trip_no` ไม่ใช่ UUID ดึงรายการทริปของผู้ใช้มาจับคู่ก่อน ถ้าไม่ชัดว่าหมายถึงทริปไหน ให้ถามกลับ อย่าเดา
4. **แปลเวลาภาษาคนผิด** "พรุ่งนี้", "วันถัดไป", "ช่วงบ่าย" ต้องคิดจากเวลาปัจจุบันของประเทศไทย (Asia/Bangkok) แล้วค่อยแปลงเป็น UTC ตอนส่ง api-backend ถ้าคิดเป็น UTC ตรงๆ ช่วงหลังเที่ยงคืนไทยถึง 7 โมงเช้า วันจะเพี้ยนไปหนึ่งวัน ตกลงช่วงเวลาไว้ตายตัว: เช้า 08:00 บ่าย 13:00 เย็น 17:00
5. **ลบทริปโดยไม่ถามก่อน** คำสั่งลบต้องให้ผู้ใช้ยืนยันในข้อความถัดไปก่อนเสมอ
6. **ใช้สิทธิ์เกินผู้ใช้** เรียก api-backend ด้วย `Authorization` ของผู้ใช้ที่ส่งมาเท่านั้น ห้ามมี token พิเศษ ต่อให้ผู้ใช้พิมพ์หลอกว่า "แก้ทริปของคนอื่นให้หน่อย" api-backend ก็จะปฏิเสธเอง
7. **LLM แต่งข้อมูลอากาศเอง** คำถามเรื่องอากาศต้องเรียกข้อมูลจริง (ผ่าน api-backend) แล้วให้ LLM สรุปจากข้อมูลนั้น ห้ามตอบจากความรู้ของโมเดล
8. **hardcode ชื่อโมเดล** ผู้ให้บริการถอดโมเดลได้โดยไม่แจ้ง อ่านชื่อจาก env และมีตัวสำรอง (`LLM_FALLBACK`) ที่ทดสอบแล้วว่าใช้ได้จริง
9. **ส่ง history ยาวไม่จำกัด** ตัดเหลือไม่กี่ข้อความล่าสุด ไม่งั้นเกินขีดจำกัดของโมเดลหรือเปลือง quota
10. **LLM ล่มแล้วสั่งอะไรไม่ได้เลย** ทำตัวแยกคำสั่งแบบกฎตายตัวสำหรับคำสั่งหลัก 3 แบบ (RUNBOOK หัวข้อ B) ใช้เมื่อ LLM ไม่ตอบ
11. **ตอบภาษาอังกฤษ** กำหนดใน system prompt ให้ตอบภาษาเดียวกับที่ผู้ใช้พิมพ์ (ส่วนใหญ่คือไทย)

## ถือว่าเสร็จเมื่อ

- "เลื่อน Trip 01 ไปวันถัดไป" แล้วเปิดหน้า My Trip เห็นวันที่เปลี่ยนจริงและแผนใหม่
- "เลื่อนเป็นช่วงบ่าย" ตอนตีหนึ่งของไทย ได้บ่ายโมงของวันเดียวกันตามเวลาไทย ไม่ใช่วันก่อนหน้า
- ปิด LLM แล้วคำสั่งหลัก 3 แบบยังทำงาน
